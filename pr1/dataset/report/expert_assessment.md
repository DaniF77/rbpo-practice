# Экспертная оценка безопасности

## Область сканирования

Диапазоны IP-адресов GitHub получены через Meta API и сохранены в датасет (`raw/github_ips.txt`, 127 диапазонов, из них 125 IPv4), но **не сканировались**: это инфраструктура GitHub, а не мои ресурсы.

Сканирование выполнено только по собственным целям:

- `192.168.0.146` - своя виртуальная машина с Debian 12 (k3s-узел);
- `127.0.0.1` - свой тестовый nginx в WSL со специально выложенной папкой `/.git/` (тестовый стенд).

Скорость Masscan ограничена (`--rate 100` и `--rate 500` в локальной сети), Nikto ограничен по времени (`-maxtime 120s`).

## Важное наблюдение про интернет-цели

Пробное сканирование `scanme.nmap.org` показало недостоверный результат: задержка 0,6 мс до американского хоста и «открытые» порты FTP, Telnet, MySQL, NetBIOS и др., которых там нет. Причина - на компьютере работает VPN-туннель (sing-box TUN), который перехватывает трафик и сам отвечает на SYN-пакеты. Вывод: сканирование через VPN/прокси даёт ложные срабатывания, такие результаты в датасет не включены.

## Критические и высокие находки

1. **Открытые 6443 и 10250 на узле Kubernetes** (Masscan) - API-сервер и kubelet. Риск: удалённое управление кластером при слабой авторизации. Рекомендация: firewall, доступ только с доверенных адресов.
2. **Доступный /.git/ на тестовом стенде** (Nikto, Nmap NSE) - риск утечки исходного кода и истории. Рекомендация: запретить доступ на уровне nginx.

## Средние находки

3. **SSH (22) и rpcbind (111)** на ВМ (Nmap). SSH ограничить по IP и только ключи; rpcbind отключить.
4. **Нет security-заголовков** (CSP, HSTS, Referrer-Policy, Permissions-Policy, X-Content-Type-Options) на обоих веб-серверах (Nikto).

## Низкие находки

5. Самоподписанный сертификат Traefik и несовпадение имени (CWE-297).
6. nginx 1.24.0 помечен Nikto как устаревший; в Ubuntu версия получает патчи безопасности отдельно, нужно проверить обновления.

## Рекомендации

1. Закрыть неиспользуемые порты и ограничить служебные порты Kubernetes по IP.
2. Добавить security-заголовки на веб-серверах.
3. Выпустить нормальные TLS-сертификаты.
4. Не выкладывать `.git` и служебные файлы в корень веб-сервера.
5. Не сканировать внешние цели через VPN/TUN: результат искажается.
6. Включить 2FA на GitHub и проверить репозитории на секреты.

## Правовое соответствие

- GitHub Bug Bounty Rules: инфраструктура GitHub не сканировалась.
- УК РФ ст. 272: сканирование проводилось только по собственным ресурсам.
